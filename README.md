# Platesh

Один сервис, который подключает приём оплаты **Telegram Stars ⭐** и **CryptoBot 💎** к любому количеству твоих Telegram-ботов. Добавляешь токены ботов в один конфиг — и все боты принимают платежи, выдают покупки и присылают тебе уведомления.

## Что умеет

- **Несколько ботов сразу.** Все боты из `config.yaml` работают одновременно в одном процессе.
- **Telegram Stars.** Нативные счета Telegram, проверка pre-checkout, возвраты.
- **CryptoBot (Crypto Pay).** USDT, TON, BTC, ETH, LTC, TRX, USDC… Цена — в долларах, рублях и т.д. (покупатель платит любой монетой по курсу) или прямо в монете. Оплата подтверждается опросом API (вебхук не нужен) или вебхуком.
- **Готовая витрина** для ботов без своего кода: каталог, карточка товара, кнопки оплаты, «Проверить оплату», `/purchases`, `/paysupport`, `/terms`, deep-link на товар.
- **Автовыдача покупки:** текст, файл, личная ссылка в закрытый канал или чат. Выданное нельзя переслать или сохранить.
- **Подписки:** доступ на N дней, напоминание перед окончанием, кнопка «Продлить», автоматическое удаление из канала, если не продлил.
- **Без оплаты — никакого доступа:** в закрытый канал пускают только оплативших, кто попал туда в обход оплаты, удаляется. Для ботов со своим кодом есть пейволл: бот не отвечает, пока не оплачено.
- **Уведомления:** админам в Telegram и POST-запросом на твой сервер (`notify_url`) с HMAC-подписью.
- **HTTP API** для ботов со своим кодом, сайтов и бэкендов. Есть готовый клиент `client/platesh_client.py`.
- **Защита от ошибок:** счёт нельзя оплатить дважды, повторная или «чужая» оплата Stars автоматически возвращается, подпись вебхука CryptoBot проверяется, счёт одного бота нельзя оплатить в другом.
- **Команды админа** в каждом боте: `/stats`, `/payments`, `/refund`, `/grant`, `/revoke`, `/access`, `/checkchats`.
- **Ключи API с ограниченными правами:** у каждого бота свой ключ, плюс ограничение по IP.
- SQLite, без внешних баз данных. Запуск на Linux, Windows и macOS или в Docker.

## Как это устроено

```
                 ┌──────────────── Platesh ────────────────┐
 бот 1 (shop) ◄──┤ витрина + Stars + CryptoBot (managed)   │
 бот 2 (shop2)◄──┤ витрина + Stars + CryptoBot (managed)   │──► уведомления админам
 бот 3 (свой  ◄──┤ HTTP API: /api/v1/invoices (external)   │──► POST на notify_url
   код)          │ опрос / вебхук CryptoBot                │
                 └─────────────────────────────────────────┘
```

У каждого бота свой режим:

| `mode` | Когда использовать | Что делает Platesh |
|---|---|---|
| `managed` (по умолчанию) | Бот нужен только для продаж, писать код не хочется | Сам запускает бота: каталог, оплата, выдача покупки |
| `external` | У бота уже есть своя логика | Не запускает бота. Создаёт счета по API, принимает оплату и шлёт уведомления |

## Быстрый старт

### 1. Получи токены

- **Бот:** [@BotFather](https://t.me/BotFather) → `/newbot` → токен вида `1234567890:AAH...`. Повтори для каждого бота.
- **CryptoBot:** [@CryptoBot](https://t.me/CryptoBot) → *Crypto Pay* → *Create App* → токен приложения. Для тестов есть [@CryptoTestnetBot](https://t.me/CryptoTestnetBot): в конфиге поставь `testnet: true`.
- **Telegram Stars** работает без дополнительных токенов.
- **Твой Telegram ID** (для уведомлений) можно узнать у [@userinfobot](https://t.me/userinfobot).

### 2. Скачай и запусти

Нужен Python 3.10 или новее (на Windows при установке отметь «Add Python to PATH»).

```bash
git clone -b claude/beautiful-johnson-i6jquz https://github.com/gytfel/Platesh.git
cd Platesh
./run.sh          # Windows: run.bat
```

При первом запуске Platesh установит зависимости и **задаст вопросы прямо в терминале**: твой Telegram ID, токен CryptoBot, токены ботов, цену и срок доступа, где лежит код бота. Токены он сразу проверит, ключи придумает сам, сохранит всё в `config.yaml` и `.env` и покажет, какие строки добавить в код каждого бота. Потом предложит запуститься.

Если указать путь к файлу бота, **Platesh сам запускает твоих ботов**: всё работает в одном терминале, вывод ботов отмечен `[имя бота]`, упавший бот перезапускается, а Ctrl+C останавливает всё вместе.

| Команда | Что делает |
|---|---|
| `./run.sh` | Запуск (первый раз — с настройкой) |
| `./run.sh setup` | Настроить заново (старые файлы сохранятся как `.bak`) |
| `./run.sh check` | Проверить токены, CryptoBot и закрытые каналы |
| `./run.sh genkey` | Придумать надёжный ключ API |

На Windows всё то же через `run.bat`: `run.bat setup`, `run.bat check`.

**Вручную, без скриптов:**
```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m platesh setup      # или: cp config.example.yaml config.yaml и заполнить
python -m platesh
```

**Docker** (настройки нужно подготовить заранее: `./run.sh setup` или вручную; ботов со своим кодом в Docker запускай отдельно — `run:` там не сработает, в контейнере нет их кода):
```bash
docker compose up -d --build
docker compose logs -f
```

После запуска **нажми `/start` в каждом боте со своего аккаунта админа**, иначе бот не сможет присылать тебе уведомления.

## Настройка (`config.yaml`)

Полный пример с комментариями — [`config.example.yaml`](config.example.yaml). Секреты лучше держать в `.env` и подставлять как `${ИМЯ}`. Запись `${ИМЯ:-}` значит, что переменная необязательна. Бот с пустым токеном пропускается, так что заготовки в конфиге не мешают.

```yaml
admins: [123456789]

cryptobot:
  token: ${CRYPTOBOT_TOKEN:-}
  currency: USD                 # или RUB, EUR… или монета: USDT, TON
  accepted_assets: [USDT, TON, BTC]

bots:
  - name: shop
    token: ${SHOP_BOT_TOKEN}
    payments: [stars, crypto]
    products:
      - id: vip
        title: VIP-канал на месяц
        description: Доступ в закрытый канал.
        price: { stars: 500, crypto: 9.99 }
        days: 30                    # подписка на 30 дней; без days — навсегда
        deliver:
          text: "Спасибо за покупку!"
          invite_chat_id: -1001234567890

  - name: other_bot
    token: ${OTHER_BOT_TOKEN}
    payments: [stars]
    products:
      - id: guide
        title: PDF-гайд
        price: { stars: 150 }
        deliver: { file: files/guide.pdf }
```

### Основные параметры бота

| Ключ | Описание |
|---|---|
| `name` | Короткое имя латиницей. Используется в API (`"bot": "shop"`) |
| `token` | Токен от @BotFather |
| `mode` | `managed` или `external` |
| `payments` | Какие способы включены: `[stars, crypto]`, `[stars]` или `[crypto]` |
| `admins` | Дополнительные админы этого бота (к глобальным `admins`) |
| `cryptobot` | Свой токен, валюта или срок счёта CryptoBot для этого бота (иначе берутся глобальные) |
| `notify_url` | Куда отправлять POST об оплатах (иначе глобальный `notify_url`) |
| `welcome`, `support`, `terms` | Приветствие, текст `/paysupport` и `/terms` |
| `texts` | Любые тексты интерфейса, ключи — в [`platesh/texts.py`](platesh/texts.py) |
| `guard` | Охрана закрытых каналов (по умолчанию `true`), см. «Защита доступа» |
| `api_key` | Отдельный ключ API только для этого бота |
| `run` | Для `external`: как запускать код бота, например `{command: "python bot.py", cwd: "C:/bots/mybot"}`. Platesh запустит его вместе с собой и передаст `PLATESH_URL`, `PLATESH_KEY`, `PLATESH_BOT`, `PLATESH_ADMINS` для `PlateshClient.from_env()` |
| `products` | Товары: `id`, `title`, `description`, `price.stars`, `price.crypto`, `days`, `deliver` |

`days` у товара включает подписку: доступ действует N дней. Повторная оплата продлевает доступ от даты окончания, а не от сегодняшнего дня, так что оставшиеся дни не сгорают. Без `days` доступ бессрочный.

### Выдача покупки (`deliver`)

| Ключ | Что происходит после оплаты |
|---|---|
| `text` | Бот отправляет сообщение (поддерживается HTML) |
| `file` | Бот отправляет файл: путь (относительно конфига), `file_id` или URL |
| `invite_chat_id` | ID закрытого канала или чата (вида `-100…`): бот создаёт туда личную ссылку. Как узнать ID: нажми `/start` в боте, затем добавь бота в канал администратором — он пришлёт ID тебе в личку |
| `invite_hours` | Сколько часов действует ссылка (по умолчанию 24) |
| `protect_content` | `true` по умолчанию: выданные сообщения и файлы нельзя переслать, скопировать или сохранить |

Можно сочетать все варианты. Если выдать покупку не удалось (например, у бота нет прав в канале), оплата всё равно засчитывается, а админы получают сообщение с ID покупателя.

**Ссылка сразу на товар:** `https://t.me/<бот>?start=p_vip` открывает карточку товара `vip`.

## Защита доступа

Покупка выдаётся только после того, как оплату подтвердил сам Telegram (Stars) или сам CryptoBot. Нажать кнопку или подделать сообщение покупатель не может.

**Закрытый канал или чат** (`invite_chat_id`):

| Что | Как работает |
|---|---|
| Вход | Покупатель получает ссылку «по заявке». Бот одобряет заявку, только если доступ оплачен и не истёк. Если ссылку перешлют другу, его заявку бот отклонит и предложит оплатить |
| Обход оплаты | Если кто-то вошёл по старой или общей ссылке без оплаты, бот сразу его удаляет и пишет ему, как оплатить (`guard: true`) |
| Окончание подписки | За 3 дня (у коротких подписок — за треть срока) бот напоминает и даёт кнопку «Продлить». В срок окончания удаляет из канала. После новой оплаты снова пускает |
| Возврат | `/refund` возвращает Stars и сразу закрывает доступ |
| Админы | Админов бота (`admins`) и админов канала охрана не трогает. Человек, которого добавил вручную админ бота, тоже остаётся |

**Настрой канал так** (проверить: `/checkchats` в боте или `python -m platesh check`; при запуске Platesh проверяет это сам и пишет админам, что не так):

1. Канал **приватный** (без @username). Публичный канал читают без подписки.
2. Бот — **администратор** с правами «Пригласительные ссылки» и (для групп) «Блокировка участников».
3. В настройках канала включено **«Запретить копирование»**: посты нельзя пересылать и сохранять.
4. Старые пригласительные ссылки канала лучше **отозвать** (Управление каналом → Пригласительные ссылки). Даже если по ним кто-то войдёт, охрана его удалит, но лучше не давать такой возможности.

**Кто уже в канале.** Telegram не даёт ботам список участников канала. Поэтому люди, которые были в канале до подключения Platesh, остаются в нём. Им можно выдать доступ командой `/grant USER_ID товар дней`, тогда по окончании срока бот их удалит. Остальных удали вручную.

Ограничение Telegram: охранять канал бот может, только если он там администратор и Platesh запущен. Пока Platesh выключен, удалять вошедших некому, но заявки на вход по ссылкам Platesh никто и не одобрит.

## Бот со своим кодом (`mode: external`)

Platesh не запускает такого бота, поэтому конфликтов с твоим кодом нет. Бот создаёт счета через API, а Platesh отслеживает оплату и сообщает о ней.

Готовые примеры: конфиг для пейволла [`examples/config.paywall.yaml`](examples/config.paywall.yaml) и бот с пейволлом [`examples/paywall_bot.py`](examples/paywall_bot.py).

1. В `config.yaml` укажи у бота `mode: external`, `api_key` (ключ только для этого бота, создать: `python -m platesh genkey`) и товары.
2. Скопируй [`client/platesh_client.py`](client/platesh_client.py) в проект бота.
3. Подключи (пример для aiogram 3):

```python
from platesh_client import PlateshClient

# Если бота запускает Platesh (run: в config.yaml) — адрес, ключ и админы придут сами:
platesh = PlateshClient.from_env()
# Если запускаешь бота отдельно — укажи их явно:
# platesh = PlateshClient("http://127.0.0.1:8080", api_key="ключ этого бота", bot="my_own_bot", admins=[ТВОЙ_ID])

# Обязательно, раньше своих роутеров: подтверждение оплат Stars, кнопки «Оплатить»/«Продлить»
# и охрана закрытых каналов. Счета, созданные не через Platesh, роутер не трогает.
dp.include_router(platesh.router())

# Пейволл: в личке бот отвечает только тем, у кого оплачен товар premium.
# Остальным показывает кнопки оплаты. /paysupport и /terms работают всегда.
platesh.install_paywall(dp, products=["premium"])
```

Без пейволла можно проверять доступ точечно:

```python
if not await platesh.has_access(message.from_user.id, product_id="premium"):
    await message.answer("Это функция для подписчиков", reply_markup=await platesh.offer_markup(["premium"]))
    return
```

Счёт можно создать и вручную:

```python
@router.message(Command("buy"))
async def buy(message: Message):
    # Platesh сам пришлёт пользователю счёт (Stars или кнопку CryptoBot):
    await platesh.create_invoice(method="stars", amount=100, title="Премиум",
                                 user_id=message.from_user.id, payload="premium", send=True)
    # Или получи ссылку и покажи её сам:
    inv = await platesh.create_invoice(method="crypto", amount="4.99", title="Премиум",
                                       user_id=message.from_user.id, payload="premium")
    await message.answer(f"Оплатить: {inv['pay_url']}")
```

Об оплате ты узнаешь из POST на `notify_url` (см. ниже) или проверкой `await platesh.get_invoice(id)`.

> `platesh.router()` обязателен для Stars: Telegram отправляет подтверждение платежа тому, кто получает апдейты бота, то есть твоему коду, а роутер передаёт его в Platesh. Результат проверки доступа клиент кэширует на минуту, чтобы не спрашивать Platesh на каждое сообщение.

## HTTP API

Авторизация: заголовок `Authorization: Bearer <ключ>` или `X-API-Key: <ключ>`. Ответ всегда `{"ok": true, "result": ...}` или `{"ok": false, "error": "..."}`.

**Ключи:**
- `server.api_key` — главный. Даёт доступ ко всем ботам и операциям. Держи его только на сервере Platesh.
- `bots[].api_key` — ключ одного бота. Его можно отдать в код этого бота. Он видит и создаёт счета только своего бота, проверяет доступы, но не может делать возвраты, выдавать доступы или трогать других ботов.
- `server.allowed_ips` — с каких адресов вообще можно обращаться к `/api/*` (например, `[127.0.0.1]`, если бот работает на том же сервере).
- Подтвердить оплату Stars через API можно только для `external`-ботов. Оплаты `managed`-ботов подтверждает сам Telegram, их не подделать даже с главным ключом.
- Создать надёжный ключ: `python -m platesh genkey`. Короткие ключи Platesh отмечает в логе и в `check`.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/health` | Проверка, что сервис жив (без ключа) |
| `GET` | `/api/v1/bots` | Боты, их режимы, способы оплаты и товары |
| `POST` | `/api/v1/invoices` | Создать счёт |
| `GET` | `/api/v1/invoices/{id}` | Счёт. `?refresh=1` — сразу проверить в CryptoBot |
| `GET` | `/api/v1/invoices?bot=&user_id=&status=&limit=` | Список счетов |
| `POST` | `/api/v1/invoices/{id}/refund` | Вернуть оплату Stars и закрыть доступ (главный ключ) |
| `GET` | `/api/v1/access?bot=&user_id=[&product_id=][&chat_id=]` | Есть ли доступ: `{"active": true, "accesses": [...]}` |
| `POST` | `/api/v1/access/grant` | Выдать доступ: `{"bot", "user_id", "product_id", "days"?, "deliver"?}` (главный ключ) |
| `POST` | `/api/v1/access/revoke` | Закрыть доступ: `{"bot", "user_id", "product_id"}` (главный ключ) |
| `POST` | `/api/v1/stars/pre-checkout` | Для `external`-ботов (используется клиентом) |
| `POST` | `/api/v1/stars/paid` | Для `external`-ботов (используется клиентом) |
| `POST` | `/webhooks/cryptobot` | Вебхук CryptoBot (проверяется подпись) |

### Создание счёта

```bash
curl -X POST http://127.0.0.1:8080/api/v1/invoices \
  -H "Authorization: Bearer $PLATESH_API_KEY" -H "Content-Type: application/json" \
  -d '{"bot": "shop", "method": "crypto", "product_id": "vip", "user_id": 123456789, "send": true}'
```

| Поле | Описание |
|---|---|
| `bot` | `name` бота из конфига (обязательно) |
| `method` | `stars` или `crypto` (обязательно) |
| `product_id` | Товар из конфига: цена и выдача берутся оттуда |
| `amount` + `title` | Или произвольная сумма (для Stars — целое число) |
| `currency` | Для `crypto`: валюта счёта (по умолчанию из конфига) |
| `description` | Описание счёта |
| `user_id` | Telegram ID покупателя: ему придёт покупка и сообщение «оплата получена» |
| `payload` | Любая твоя строка (например, номер заказа). Вернётся в уведомлении |
| `send` | `true` — Platesh сам отправит счёт пользователю в бота |

Ответ — объект счёта: `id`, `status` (`pending` / `paid` / `expired` / `refunded` / `failed`), `pay_url`, `amount`, `currency`, `paid_asset`, `paid_amount` и др.

## Уведомления на `notify_url`

После оплаты (и возврата) Platesh отправляет POST с JSON. При ошибке он повторяет запрос через 5 с, 30 с, 2 мин и 10 мин.

```json
{
  "event": "invoice_paid",
  "invoice": {"id": "a1b2c3d4e5f6", "bot": "shop", "method": "crypto", "amount": "9.99",
              "currency": "USD", "status": "paid", "user_id": 123456789, "product_id": "vip",
              "paid_asset": "USDT", "paid_amount": "9.99", "payload": "order-42", "...": "..."},
  "access": {"product_id": "vip", "expires_at": 1767225600, "active": true},
  "bot": {"name": "shop", "id": 1234567890, "username": "my_shop_bot"},
  "user": {"id": 123456789, "username": "buyer", "first_name": "Иван"}
}
```

`access` есть, если оплачен товар из конфига (`expires_at: null` — навсегда). Когда подписка заканчивается, приходит событие `access_expired` с полями `access` и `user`.

Заголовки: `X-Platesh-Event: invoice_paid | invoice_refunded | access_expired` и `X-Platesh-Signature`. Подпись — HMAC-SHA256 от тела запроса с ключом `server.webhook_secret`. Проверка на Python:

```python
from platesh_client import verify_webhook
```

## Вебхук CryptoBot (необязательно)

По умолчанию Platesh каждые `poll_interval` секунд опрашивает CryptoBot. Публичный адрес для этого не нужен. Если у сервера есть HTTPS-домен, можно включить мгновенные уведомления: @CryptoBot → Crypto Pay → My Apps → твоё приложение → Webhooks → `https://твой-домен/webhooks/cryptobot`. Опрос можно оставить как подстраховку.

## Команды в ботах

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | Каталог товаров |
| `/purchases` | все | Мои доступы (до какого числа) и покупки |
| `/paysupport` | все | Помощь с оплатой (Telegram требует её от ботов, принимающих Stars) |
| `/terms` | все | Условия (если заданы `terms`) |
| `/admin` | админы | Список команд админа |
| `/stats` | админы | Выручка за сегодня и за всё время, по этому боту и по всем ботам |
| `/payments` | админы | Последние счета |
| `/invoice ID` | админы | Подробности счёта |
| `/refund ID` | админы | Вернуть оплату Stars и закрыть доступ |
| `/grant USER_ID товар [дней]` | админы | Выдать доступ без оплаты (подарок, перенос старых подписчиков) |
| `/revoke USER_ID товар` | админы | Закрыть доступ и удалить из канала |
| `/access USER_ID` | админы | Доступы пользователя и сроки |
| `/checkchats` | админы | Проверить настройки закрытых каналов |

## Полезно знать

- **Stars** зачисляются на баланс бота. Вывести их можно через Fragment по правилам Telegram. Возврат Stars делается командой `/refund` или через API.
- **CryptoBot** зачисляет крипту на баланс твоего приложения Crypto Pay. Автоматического возврата там нет: возвращай вручную через @CryptoBot.
- Telegram требует продавать **цифровые товары и услуги** внутри ботов за Stars. Учитывай это, когда включаешь крипто-оплату для таких товаров.
- Один токен бота может принимать апдейты только в одном месте. Поэтому бота, у которого уже есть свой код, подключай в режиме `external`.
- Все счета и покупатели хранятся в `data/platesh.db` (SQLite). Делай резервные копии этого файла.

## Разработка

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты подменяют Telegram и CryptoBot и проверяют весь путь: витрину, Stars (pre-checkout, оплату, двойную оплату, возврат), CryptoBot (опрос, вебхук с подписью, истечение счёта), подписки (продление, напоминания, удаление из канала), охрану входа, права ключей API, уведомления, пейволл и клиент для `external`-ботов.

Структура:

```
platesh/
  config.py        загрузка и проверка config.yaml
  payments.py      ядро: счета Stars/CryptoBot, приём оплат, возвраты
  access.py        доступы и подписки, удаление из каналов, проверка каналов
  cryptopay.py     клиент Crypto Pay API
  delivery.py      выдача покупки
  notifier.py      уведомления админам и на notify_url
  db.py            SQLite
  web.py           HTTP API и вебхук CryptoBot
  bots/shop.py     витрина и обработчики оплаты
  bots/admin.py    команды админа
  app.py           запуск всего вместе
client/platesh_client.py   клиент для ботов со своим кодом
```
